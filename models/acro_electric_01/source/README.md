# Acro Electric 01 — Blender source

`acro_electric_01.blend` is the editable DCC source for the Acro Electric 01 presentation asset.

**It is not a runtime dependency.** Nothing in `crates/`, the renderer, the simulation, physics or
replay reads this file, and `test_asset_contract.py` fails if that ever stops being true. The
runtime authority remains the exported GLB (`../aircraft.glb`), and the articulation authority
remains `../model.json -> presentation.articulated_surfaces`.

## Regenerating

The file is fully regenerable from the committed GLB:

```cmd
"C:\Program Files\Blender Foundation\Blender 5.2\blender.exe" --background --python-exit-code 1 ^
    --python tools/aircraft_asset_pipeline/blender_import_reference.py ^
    -- --asset-id acro_electric_01 --force
```

Regeneration is **not** byte-identical — Blender embeds its own save metadata, so three
independent runs produced three different files. The exported GLB *is* byte-identical across all
three, which is what actually matters. Details and measurements are in
`tools/aircraft_asset_pipeline/README.md` under "Reproducibility".

Because regeneration is cheap and non-reproducible at the byte level, do not hand-edit this file
and commit it without also recording what you changed in the manifest. Prefer editing → validating
→ exporting to scratch → reviewing, and only then deciding whether a production cutover is wanted.

## What is inside

Scene `Acro Electric 01`, metric units, `scale_length = 1.0`, metres.

Every object is a direct child of `ACRO_ROOT`. Object names are the stable semantic ids; each
object also carries `rc_semantic_id`, `rc_primitive_index`, `rc_legacy_node_name`, `rc_family`,
`rc_asset_id` custom properties, plus `rc_moving_surface` and `rc_control_surface_binding_id` on
the four control surfaces. Those properties are pipeline metadata: `export_extras` is off, so they
never reach the GLB, and the runtime never infers anything from a name.

Blender frame is `+X` right, `+Z` up, `-Y` forward. Render-body / glTF frame is `+X` right, `+Y`
up, `-Z` forward. Conversion is `blender = (x, -z, y)`.

Scale is exactly `1.0` and rotation exactly identity on every object. Location is the authoring
pivot: the declared hinge line for `AILERON_L`, `AILERON_R`, `ELEVATOR` and `RUDDER`, world origin
for everything else. `blender_export_glb.py` bakes those pivots into the mesh data at export time,
so the pivots survive in the source for articulation work instead of being flattened by an Apply
Transform.

Geometry is a semantic reorganisation of the existing G3C-B procedural asset — same silhouette,
same topology, same eight materials. It is not remodelled art. `WING_MAIN_FIXED`, `HTAIL_FIXED`,
`GEAR_MAIN` and `WHEELS` are single objects because that is how the source geometry exists;
per-side splits are not invented here.
